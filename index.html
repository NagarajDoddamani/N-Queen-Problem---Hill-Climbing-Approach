The N-Queen Problem

Place N queens on an N×N chessboard such that no two queens threaten each other. A queen attacks in all 8 directions — horizontally, vertically, and diagonally.

Two queens in the same row attack each other horizontally.
Same Column Conflict
Two queens in the same column attack each other vertically.
Diagonal Conflict
Two queens on the same diagonal can attack each other.

AI PERSPECTIVE

Why AI Solves This

The N-Queen problem is a classic AI benchmark. Brute force fails at scale — AI heuristic search cuts through the exponential state space intelligently.

⚡

🎯

We minimize the heuristic h(n) = number of attacking queen pairs. Goal is h(n) = 0.
🔗

THE ALGORITHM

Hill Climbing Algorithm

Hill Climbing is a local search algorithm that continuously moves toward better states by evaluating neighbors. Think of it as always climbing uphill (or in our case, always reducing conflicts).

1
🎲
Random Initial State
Place one queen per column at a random row. This is our starting board configuration.
2
📐
Heuristic h(n)
Count all pairs of queens attacking each other. h(n) = 0 means solution found.
3
🔢
Generate Neighbors
For each column, try moving that queen to every other row. N×(N-1) neighbors generated.
4
🏆
Select Best Neighbor
Pick the neighbor with the minimum heuristic value — the move with fewest conflicts.
5
🚀
Move to New State
If best neighbor improves h(n), move there. Update the board and recalculate.
6
🔄
Repeat / Stop
Repeat until h(n)=0 (solution) or no neighbor improves state (local maximum).

PSEUDOCODE

Algorithm Code

The formal pseudocode representation of the Hill Climbing algorithm applied to the N-Queen problem.

hill_climbing_nqueen.py
// Hill Climbing — N-Queen Solver   function hillClimbing(n): board ← randomState(n) // one queen per column current_h ← heuristic(board) // count attacking pairs   while True: if current_h == 0: return board // ✓ Solution found!   neighbors ← generateNeighbors(board, n) best ← minBy(neighbors, heuristic) best_h ← heuristic(best)   if best_h >= current_h: return LOCAL_MAXIMUM // ⚠ Stuck!   board ← best // Move to better state current_h ← best_h   function heuristic(board): attacks ← 0 for each pair (i, j) where i < j: if sameRow(i,j) or sameDiag(i,j): attacks += 1 return attacks
ANALYSIS

Advantages & Limitations

Advantages
▶
Memory Efficient — O(N)
Only stores current state, not entire search tree.
▶
Fast Convergence
Quickly moves toward better states without exhaustive search.
▶
Simplicity
Easy to implement and understand. No complex data structures needed.
▶
Scalable
Works for large N where brute-force is infeasible.
Limitations
▶
Local Maximum Problem
Can get stuck where no neighbor is better, but solution not found.
▶
No Backtracking
Cannot recover from a bad decision — only moves forward.
▶
Not Complete
Does not guarantee finding a solution even if one exists.
▶
Initial State Dependent
Quality of solution depends heavily on starting configuration.
LOCAL MAXIMUM PROBLEM

When Hill Climbing Fails

A local maximum occurs when every neighboring state has a higher (worse) heuristic than the current state — the algorithm gets trapped and cannot escape without restarting.

⚠ All moves increase conflicts — LOCAL MAXIMUM REACHED
⛰️
What is a Local Max?
A state where h(n) cannot be reduced by any single queen move, but h(n) ≠ 0.
🎯
Plateau Problem
A flat region where all neighbors have equal h(n). Algorithm wanders without progress.
🔄
Solution: Restart
Random Restart Hill Climbing retries with a new random state, improving success rate significantly.
COMPLEXITY ANALYSIS

Time & Space Complexity

TIME COMPLEXITY
O(N²)
Per iteration, we evaluate N×(N-1) neighbors, each requiring O(N) heuristic computation. Overall: O(N²) per step with typically O(N) steps needed.
SPACE COMPLEXITY
O(N)
Only the current board state (array of N positions) needs to be stored. No search tree maintained — this is the key advantage over BFS/DFS.
NEIGHBOR STATES
N(N-1)
For each of N columns, we can move the queen to N-1 other rows, generating N×(N-1) unique neighbor states per iteration.
SUCCESS RATE (N=8)
~86%
Hill Climbing solves 8-Queen ~86% of the time. With Random Restart enabled, success rate approaches 100% within a few restarts.
vs Brute Force
Brute Force: O(N!) — For N=12, that's 479 million states.
Hill Climbing: O(N²) per step — Far more tractable.
Random Restart
Expected restarts for N=8: ~1.2
Each restart is O(N²) — very fast in practice.
